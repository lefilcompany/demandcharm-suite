# Finance rules
- Shared expenses with method `revenue_pct` charge each board `allocation_pct`% of its own gross in `_finance_allocations` (mirror `allocation.ts`), never re-dividing the amount — a new contract never lowers the others; shortfall stays "unallocated", excess is "surplus" (negative null-board row in `get_finance_allocation`, netted in the closing checklist).
- Team standard values (tax, variable, allocation %, margin, max discount) live in versioned `finance_team_defaults` and are read for every project month through `_finance_team_rates` — `finance_project_settings` is DEPRECATED and the project screen only shows those team values read-only; man-hour cost is the weighted average from RPC `finance_team_hourly_cost` (per-person costs, never exposed individually), and project minimum price uses pure `src/lib/finance/pricing.ts`.
- Per-person man-hour cost is one global config per team+person (`finance_member_rates`, valid until changed), read only through `_finance_member_cost`, which still returns the stored monthly row for months already closed — so an open month never needs a new launch and closed numbers never move.
- Finance E2E lives in `e2e/finance_e2e.py` (Playwright, preview session); it tags data `E2E-FIN-*` and deletes it at the end because preview and production share one database.
- Finance month cuts on timestamps use `_sp_month`/`_sp_month_start` (São Paulo), like `_finance_time_slices` — so screens agree at month ends.
- Project personnel cost and hours come only from `_finance_project_staffing`: contracted monthly cost/hours of internal, non-requester members of the project's boards, split equally across the active projects each person belongs to — timer hours (`_finance_time_slices`) are kept only for audit and planned × realized, so a person is never counted twice.
- Project×month numbers come only from `_finance_project_month`, shared by RPC `get_project_finance_overview` and Edge `finance-api-v1` (sha256 `sk_fin_` keys) — UI and external panel never diverge.
- Closing snapshots each finance-enabled project (`finance_project_snapshots`); `_finance_project_month` serves it plus its boards' adjustments — closed numbers match everywhere.
- Team fixed/operational/admin costs live in versioned `finance_team_costs` (valid until changed) and are split equally across finance-enabled projects active in the month (`_finance_team_cost_share`, mirror `projectShare.ts`); `_finance_project_month_live` uses it whenever the team has any team cost, falling back to legacy shared-expense allocations otherwise — so old months keep their numbers.
- Project revenue is stored in `finance_revenues` with `project_id` (board_id kept as reference for RLS); project months count rows with that project_id or, when null, rows of its boards — never both.
- Creating a project notifies the owner and the finance revenue managers in-app (trigger `trg_notify_project_created`, type `project_created`) and by e-mail (frontend `notifyProjectCreatedEmail` → Edge `send-email`); the creator is never notified and a failing e-mail never blocks creation.
- The team's total revenue for a month comes only from RPC `get_team_revenue_summary` (SECURITY INVOKER, so RLS applies); rows without a project are shown as "Sem projeto" so the team total never double-counts.
- The team overview (`_finance_overview_all`) includes team costs (month total ÷ active projects, each part split equally over the project's boards) instead of legacy allocations whenever team costs are configured, and counts project revenue split the same way at the team tax rate — so the overview total matches the sum of the projects.
- Project revenue is launched as a contract (total + start + duration in days/months/years) and stored as monthly `finance_revenues` rows sharing `contract_id`, split by pure `src/lib/finance/revenueContract.ts` — so every monthly aggregation keeps working unchanged.
